# 资料管理与地图缓存

## 本地工具

在 `E:\CMIT\AIassistance\server` 打开PowerShell：

```powershell
node scripts/manage-data.js report
node scripts/manage-data.js export E:\CMIT\AIassistance\content-draft.json
node scripts/manage-data.js import E:\CMIT\AIassistance\content-draft.json
node scripts/manage-data.js import E:\CMIT\AIassistance\content-draft.json --apply
```

`report` 生成 `docs/资料管理/资料管理.html` 和检查JSON。管理页可查看五处资料状态、编辑完整JSON并下载草稿；下载时只检查JSON语法。命令行 `import` 默认只预检，`--apply` 才执行导入：检查来源关联、字段、公开边界及已核入口证据，备份旧文件、写入新文件、记录版本。导入后重启服务生效。备份在 `server/data/backups`，回滚可将对应旧JSON作为导入文件先预检再应用。未新增公网管理员接口或假登录。

入口启用必须补 `entranceEvidence`：method为official_entrance_map或onsite_record，reviewer、checkedAt、position、record、sourceIds及coordinate齐全。证据坐标应与入口坐标一致，sourceIds包含坐标来源。字段齐全是结构门槛，不能代替真实证据审核；不能填写虚假核验人或现场记录。来源本身是地图POI，不足以证明游客入口。尚无证据时coordinate保持null或verified=false。

## 路线缓存

每个服务实例独立，最多100条，有效期3分钟，定期清理，停服清空，不写磁盘。仅缓存成功且已解析的完整步行响应；错误、未核入口、暂停开放均不会靠缓存绕过检查。缓存键使用SHA-256，包含精确起点、站点顺序、入口及开放字段、模式和服务凭据的散列输入；不输出原密钥。改变坐标、顺序、开放字段或Key会失去原命中。

返回 `cacheHit` 和原始 `generatedAt`，缓存命中不会伪造新的路线生成时间。用户起点和折线仅短时存在进程内存，不落盘；没有跨用户聊天缓存。现已合并相同步行请求；新增本机POI候选查询10分钟、50条缓存及相同请求合并。候选不会直接写入入口。详见《缓存与回滚演练更新.md》。
