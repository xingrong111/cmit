## 内容结构

来源字段：`id/title/institution/publishedAt/accessedAt/url/finalUrl/position/excerpt/relation`。日期未显示写“未显示”。来源失效时记录取得情况和旧链接，不补造替代地址；本版样例均本轮取得了正文。

事实字段：`id/personId/personName/eventIds/text/keywords/sourceIds/reviewStatus/published`。`text` 写一个可直接核查的事实组；团队增加人物时应填写personName，避免提到明确人物却检索到其他人的卡片。关键词应包含常用别称，但别称不替代身份核对。

场馆字段：`id/name/city/type/address/summary/visitFocus/personIds/relatedPeople/sourceIds/coordinate/opening/reviewStatus/published`。`visitFocus` 是到场阅读建议，不能据建议反推馆内确有某件实物。

类型使用“故居”“纪念馆”等统一值；新的类型需同步筛选控件。地点ID与人物ID分开，不让一座纪念馆成为另一个人物计数。

## 坐标如何补

当前三处坐标都为null。请先取得官方导览图/馆方入口说明与可核查的地图POI，检查游客入口而非建筑中心、旧址或员工通道，保存依据和核查时间。地图服务POI不是馆方营业公告；不同证据分别记录。

核对后结构示例（数值必须替换为实际核验值，不直接复制占位值）：

```text
coordinate:
  type: gcj02
  latitude: 实际纬度数值
  longitude: 实际经度数值
  verified: true
  sourceId: 坐标依据对应的来源ID
  checkedAt: 实际核查日期
  reviewer: 实际审核人
```

WGS-84、百度BD-09不能直接填进GCJ-02字段。微信 `getLocation({type:'gcj02'})` 已请求兼容坐标。城市地址不能用手绘偏移或模型猜测补坐标。

## 开放和预约如何补

有馆方/官方当期公告才填写 `opening:{status,text,checkedAt,sourceId}`。status可用open/closed/unknown；text包含开放时间、预约方式、适用日期及必要联系说明。没有当期依据保持null。服务端对超过7天、无效或未来的checkedAt回退“尚未核实”；这7天是本项目保守的刷新阈值，不是官方保证有效期。

即使信息显示近期open，也应出发前确认临时调整。closed仅在最近资料有效时阻止路线；不会依据多年旧报道永久判定闭馆。

## 逐条导入流程

1. 保存原始URL、最终URL、机构、日期、证据短摘录与准确位置；原件、回忆、报道、转载分别说明。
2. 将事实或场馆设draft，只用于整理，不显示到试读页面。不同来源有冲突设conflict，不能靠语言顺畅跳过。
3. 读正文核对后可设source_checked进行本地试读；这里不等于独立审核完成。
4. 由其他审核人核对姓名、日期、关系、来源直接支持情况。记录审核人、审核日期和结论，再设verified；获得公开发布授权后设published:true。
5. `npm run validate`，重启服务检查引用和客户端展示。该命令只是结构检查，审核签字需人工留档，系统不会代签。

没有图片授权记录时不增加人物照片；本模块的页面装饰为代码绘制，不冒充历史建筑照片或人物复原。对于此前资料里的争议字段先记录原因、来源，保持未发布，不需要无限深挖才能继续开发。
